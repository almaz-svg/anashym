# Аудит полного цикла заказа

Дата: 2026-10-18. Проверка REST-контракта `docs/mvp-contract.md` через Django APIClient и временную SQLite test database. Сервер, отдельная БД и worker не запускались.

## Добавленные сценарии

`backend/shop/test_order_cycle_audit.py` содержит 8 приемочных тестов:

1. FEFO резерв 5 порций из двух партий (3+2), назначение курьера, выезд, частичная доставка 3 порций по сохраненной цене 1500 после изменения каталога на 1800. Остаток 2 остается у курьера до физической сдачи, затем уходит в карантин без увеличения продаваемого склада. Повтор сдачи с тем же ключом не удваивает движение. Обмен одной доставленной порции: одобрение без приема еще не кредитует клиента, физический прием создает кредит 1500, новый заказ резервирует товар по новой цене 1800 и доставляется независимо от старого. Итоговый баланс 4800, доступный склад 4, кредитный резерв 0.
2. Отмена до выезда освобождает оба FEFO резерва и кредит; повтор запроса не меняет остатки, начислений нет.
3. Неудачная доставка сохраняет товар у курьера и не начисляет долг. Повторный выезд не списывает склад второй раз; успешная доставка создает одно начисление и вторую попытку.
4. Pending возврат резервирует доступное для возврата количество. Повтор сверх доставленного отклоняется; отклонение исходного возврата освобождает этот лимит.
5. После неудачной доставки и полной физической сдачи разрешена окончательная отмена, освобождающая только кредит этого заказа. Другой активный заказ сохраняет резерв; идемпотентный повтор и stale version не освобождают его повторно.
6. Частичная доставка без причины откатывает изменения целиком: принятые количества, товарные движения, ledger и кредит.
7. Повтор успешной доставки с тем же ключом возвращает сохраненный ответ; новый ключ со старой версией отклоняется. Начисление, списание и попытка доставки не дублируются.
8. После частичной физической сдачи неудачной доставки отмена запрещена, пока товар остается у курьера; повторный выезд с неполным товарным составом также запрещен.

## Найденный и исправленный дефект

В исходной реализации цепочка deferred order → dispatch → delivery-failed → goods-return всех товаров оставляла заказ навсегда в `delivery_failed` с занятым кредитным лимитом. Отмена возвращала 409, а повторный выезд без товара возвращал 200 и приводил к невозможной доставке.

Причина: `workflow.transition` разрешал из `delivery_failed` только повторный выезд; `goods-return` удалял custody reservations, сохраняя кредит до завершения заказа. Повторный выезд не проверял оставшийся товар.

Изменен только `backend/shop/workflow.py`: отмена failed-заказа разрешается после полной физической сдачи при наличии зафиксированной неудачной попытки; оставшийся кредит освобождается в этой терминальной транзакции. При повторном выезде проверяется, что у курьера есть все недоставленные позиции в полном количестве. Прямая отмена с товаром у курьера остается запрещенной. Новые тесты сначала воспроизвели оба дефекта (409 вместо 200 для отмены; 200 вместо 409 для повторного выезда).

Согласование контракта: правило «cancel до выезда» следует дополнить разрешенной окончательной отменой после неудачной попытки и полной физической сдачи. Это не разрешение отменять товары, которые еще находятся у курьера.

## Ограничения

APIClient использует force_authenticate; здесь не проверяются браузерные cookie/CSRF, UI, реальная загрузка файлов, Celery, PostgreSQL-конкуренция и сетевой деплой. Фото — существующие metadata fixtures, без записи файлов. Финансовый аудит платежей/кассы, роли и предзаказы проверяются отдельно. PASS этих сценариев не означает полную приемку всей системы.
